# Koide 1.x 路线

这些是规划，不代表已实现。1.0 先完成产品打磨、Rich Diff、CI 和 RC 验收；用户确认 1.0 发布后才进入下一阶段。

| 版本 | 重点 | 边界 |
|---|---|---|
| 1.0 RC | 面板手感、连续状态、历史 Diff、空/错误状态、移动端一致性 | 收敛现有体验，不集中加入下一代功能 |
| 1.1 | 语义项目索引、上下文固定、持久任务 | 索引符号/引用/调用/依赖；显式展示模型可访问的上下文；任务状态与项目记忆分离 |
| 1.2 | 执行计划图、调试调查视图 | 计划与真实执行分开；显示已执行/失败/跳过/替换；工程判断依据错误、工具、实验与验证 |
| 1.3 | 多 Agent 子任务、Git Worktree 沙箱、Checkpoint 分叉 | 真实任务与产物；主 Agent 管理依赖、冲突和合入；应用回主工作区由用户控制 |
| 1.4 | AI UI Inspector、视觉回归 | 从实际元素追溯 DOM/CSS/事件/状态/源码；区分预期视觉变化与回归，覆盖多视口与主题 |

## 贯穿路线的能力

- **架构地图**：以语义索引为基础，追踪组件 → Runtime API → Native dispatch / Bridge → 实现文件，节点必须来自真实分析。
- **可审计动作解释（Why?）**：依据 Tool Call、Diff、Checkpoint、错误、验证和任务目标说明动作原因，不展示或伪造隐藏思维链。
- **本地 AI Code Review**：检查当前工作区差异中的回归、死代码、接口不一致、移动端和无障碍问题；默认用安静的状态提示，由用户展开。
- **连续状态变化**：持续改善发送/停止、准备/读取/修改/验证和工具卡状态的视觉连续性，不阻塞输入。
- **Android 语义触觉**：考虑面板吸附、危险确认、任务完成和恢复等少数节点；需要原生能力、系统设置与用户开关，不用每次点击震动充数。

## 长期约束

项目记忆只保存用户显式维护的长期知识。持久任务保存任务目标、计划、读取与修改记录、验证、检查点和未完成步骤。两者不能混为自动聊天摘要。

时间线、调查过程和多 Agent 活动必须来自实际事件，不能补造工具调用、假成功或不存在的验证。计划改变时保留变更痕迹，不能把计划伪装成执行记录。

Koide 的方向是让 AI 软件工程可见、可控、可审计、可撤回、可理解、可验证。
